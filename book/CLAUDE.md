# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this directory is

`book/` holds the chapter content for *Decoding Health Data*, a book written by Daniel Feller (PhD, Biomedical Informatics, Columbia, 2020; now builds health tech startups) and published as a section of his Jekyll portfolio site (repo root is one level up, at `../`). There is no separate build system here — chapters are plain Markdown files rendered by the site-wide Jekyll config and the shared `book` layout.

## Audience and purpose

The book has two intended audiences at once, and chapter content should serve both:
- Established data scientists/engineers moving into medical or clinical work who need grounding in how healthcare data is generated and structured.
- Practitioners already working in one healthcare/life-sciences domain (e.g. claims, EHR) who want to expand into adjacent domains they don't know well (e.g. genomics, medical imaging).

Chapters should stay accessible to both: don't assume deep clinical background, but don't over-explain general data/engineering concepts. It's currently distributed for free online at danieljfeller.github.io/book; Daniel intends to eventually pursue formal publication, so content should be treated as publication-quality prose, not blog-post drafts.

## Site build

The Jekyll site (title, plugins, exclusions) is configured in `../_config.yml`. There is no `Gemfile` checked into the repo and Jekyll is not installed locally in this environment, so `bundle exec jekyll serve` (as suggested by the root `README.md`) will not work out of the box — treat that as aspirational unless a Gemfile is added and gems are installed. GitHub Pages builds the site remotely using its default supported gems on push to `main`.

## Chapter structure

Every chapter is a Markdown file with Jekyll front matter:

```yaml
---
layout: book
title: "Chapter Title"
permalink: /book/<part>/<slug>/
---
```

Chapters are grouped into part directories: `intro/`, `administrative/`, `clinical/`, `patient-generated/`, `working-with-data/`. Chapter length varies widely — some are fully written (e.g. `clinical/ehr.md` at ~360 lines), others are short stubs (6–20 lines) awaiting content.

**Adding or renaming a chapter requires updating three places in sync**, since there is no data-driven table of contents:
1. The chapter file itself (front matter `permalink` + content).
2. The chapter list in `book/index.md` (the book's landing/TOC page).
3. The sidebar nav in `../_layouts/book.html`, which hardcodes the same links per-part with `{% if page.url == '...' %}` active-state checks.

All three must agree on the exact `permalink` path or the sidebar's active-link highlighting will silently break.

## Styling

The book layout and sidebar/chapter styling live in `../_layouts/book.html` and `../assets/css/book.css`, shared across all chapters — don't duplicate layout HTML inside chapter Markdown. Chapter content is otherwise plain Markdown (kramdown); custom HTML blocks (e.g. `<div class="book-cover-hero">`) are only used on `index.md` for the cover/hero section, not in regular chapters.

## Figures

Figures live in `../images/book/` and are embedded with a `<figure>` block in the chapter Markdown (kramdown passes the HTML through):

```html
<figure>
  <img src="{{ '/images/book/<slug>.svg' | relative_url }}" alt="...">
  <figcaption>...</figcaption>
</figure>
```

Use **straight ASCII quotes** in the Liquid tag — curly quotes break the `relative_url` filter and the image won't resolve.

Figures should be **SVG** authored to the book's visual standard (Nature-style, tinted to the site). The standard, palette, and starter templates are owned by the `health-data-figure` skill (`../.claude/skills/health-data-figure/`) — invoke it rather than styling a figure ad hoc. Every book figure fits one of four families it templates: file-format layouts, workflow/pipeline diagrams, quantitative charts/time series, and conceptual schematics. All chapter figures are SVG (only `../images/book/cover.png`, the book cover, remains a raster). Several data figures use illustrative synthetic data — say so in the `<figcaption>`. Many charts are generated by short deterministic Python scripts; when a figure needs new data, regenerate rather than hand-editing hundreds of path coordinates.
